## network-creation (REST)

- **APPROVED** — Switch DI guidance for API clients/repositories from `@injectable` (factory) to `@lazySingleton` (community consensus; stateless, no reason to re-instantiate).
- **APPLIED** — Explicit Dio timeouts rule (Critical Rule 6 + checklist).
- **APPLIED** — "Token refresh out of scope until the package interceptor lands" note.
- **PUBLISHED (2026-07-10)** — Token refresh shipped as simple_network_handler **v1.2.0** on pub.dev: `RefreshTokenInterceptor` (QueuedInterceptorsWrapper, single-flight, bare-Dio refresh+replay), `RefreshRequest` spec, abstract `TokenStore`; must be ordered BEFORE `ErrorMappingInterceptor`. 21/21 tests. The network-creation skill's "token refresh out of scope" note was replaced with v1.2.0 wiring guidance. Design rationale kept for reference: `QueuedInterceptor` pauses concurrent requests on 401 → single-flight refresh on a **separate bare Dio** (same-instance retry deadlocks: dio #1612; interceptor-free avoids 401 loops) → replay queue with new header → `onRefreshFailed` force-logout callback.
- **APPROVED (simple_network_handler v2)** — Migrate `Either<Failure, T>` (dartz) → hand-rolled Dart 3 `sealed class Result<T>` (`Ok`/`Err`) as a **major version (2.0.0)** so existing apps stay on 1.x unbroken. Self-describing names, zero dep, compiler-exhaustive `switch`, kills the fold-discards-failure defect class. Do after the 1.1.0 token-refresh release ships.

- **KEEP** — Registry/interceptor error mapping (hybrid: interceptor classifies, safeCall translates). Aware of dio onError edge-case issues (#2120/#2138) and that official guidance maps at the repository.

## network-creation-supabase

- **APPROVED** — RLS asymmetry rules: SELECT under RLS silently returns EMPTY (no error — don't map empty to not-found without ruling out policy/JWT); RLS-violating writes throw `42501`; `.insert(...).select()` read-back runs under the SELECT policy → a successful write can surface as PGRST116 ("visibility error, not a write error" — never blindly retry mutations on it).
- **APPROVED** — `timestamptz` params: `.toUtc().toIso8601String()` (plain `toIso8601String()` on local times omits the offset). Extends the existing `date` rule.
- Noted for other migrations: v2 `Supabase.initialize()` doesn't validate the restored session — gate startup on `onAuthStateChange` (→ auth-flow-supabase); never mock `SupabaseClient` with mockito (isolate timeout, #714) — use `mock_supabase_http_client` or repository fakes (→ unit-testing).
